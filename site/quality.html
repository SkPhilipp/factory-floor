Quality control

A dark factory has no one watching, so quality cannot come from watching. It comes from three things: a quality gate the agent must pass before it may hand off, artifacts with a shape the factory can refuse, and a reviewer that trusts neither the builder nor its summary.

Artifacts with a shape

ArtifactPath on the branchRefused when
the plan from Intakefactory/plans/N-A.mdmissing; a section is missing; no acceptance criterion; a proof is not a runnable command
the gate report from Buildfactory/gates/N-A.mdmissing, failing, or not for the pushed commit
the review from Reviewfactory/reviews/N-A.mdmissing; a criterion from the plan is not mapped; the verdict is not one of two words; READY with an open item

A refused artifact is a technical failure. The agent is told exactly which rule it broke and tries again.

What counts as proof

An artifact a stranger can verify without trusting the author.

ClaimProofVerified by
it lints and teststhe check command's output, exit code shownthe quality gate, run by the agent, re-run by the factory
it does what the plan askedeach proof command from the plan with its outputthe quality gate
the phase did its jobthe phase's artifact exists under factory/ with its sectionsa command the factory runs at the end of the phase
it stayed inside the planthe diff touches only allowed files, within budgetthe quality gate, then the Review agent
it rendersa screenshot written by a proof command at a stated viewportthe gate runs the command, the reviewer looks
it is the whole issueeach acceptance criterion mapped to lines in the diffthe Review agent, shape-checked by the factory
it is only the issueno unrequested change listed in the reviewthe Review agent

Not a proof: "I ran the tests and they pass" without output. "Verified manually". A summary of what was done. Those are claims. Proofs are attached to the pull request, not the thread, because the pull request is what survives. The thread is the shop floor; the pull request is the shipping label.

Layers, and what each catches

LayerCatchesCost
Artifact shapeagents that skipped a section or a criterionmilliseconds, no model
Quality gate: checksstyle, dead code, obvious mistakes, broken testsseconds, no model
Quality gate: proofs and constraintsagents that claim without doing; scope creep by fileseconds, no model
Merge checkbranches that no longer merge cleanlyseconds, no model
Review agentmissing criteria, unrequested changes, defects the tests do not coverone model call
Releasethe merge and the deploy, by the systemminutes, no model

The order is the order of cost. Nothing reaches the next layer until the cheaper one passed. No human approves a merge; the human reads what shipped, after the fact, and what they would have changed becomes the next task on the Backlog. Human review capacity stops being rationed and starts being built, by adding checks the layers can run.

Failure modes

the confident wrong agent
caught by the gate re-running the proofs and by the reviewer
the scope creeper
caught by the plan's constraints at the gate and the unrequested-changes section in the review
the flaky check
caught by CI disagreeing with the gate
the stalled loop
an agent waiting on a prompt nobody answers, caught by full permissions inside the workspace and by the phase timeout
the runaway loop
a task failing and re-entering forever, caught by the five-strike cap
the conflicting pair
two builds touching the same files, caught by the merge check at the start of Review
the unplannable request
caught by the Intake weight, one failure there is final
