An agent is a prompt. A harness is what turns the prompt into a session with a shell, a file system, a git identity and a stopping rule. The factory has two layers of it: Claude Code runs one session, bb starts sessions, isolates them, and hears when they stop. Both run in one Docker container.

Claude Code

Claude Code is the session runner for every agent. Sessions run non-interactively with full permissions inside their workspace and end in a clear idle state, which is what the factory listens for. The working agreement lives in the repository's instructions file, so a session started by hand behaves like a dispatched one. The factory's commands, including the quality gate, are exposed to the agents as a skill and as an MCP tool. Sessions, settings and memory persist in one home directory, which is one volume.

bb

bb manages projects, threads and environments for coding agents, and runs plugins against them. Four primitives carry the loop, as a list with bold lead-ins:

  • Worktree environments give a thread its own branch and directory. The factory creates one per task at Intake and spawns the Build and Review threads, and every retry's threads, into that same environment. This is the hard guard: an agent can only reach its own branch, and merging into main is done by the factory, never by an agent.
  • Lifecycle events let a plugin react the moment a thread goes idle or fails. Hand-off checks, timeouts and strikes are a plugin listening on those events.
  • Threads read each other: a thread can open another thread's content, so a retry's agents read the failed attempts' threads by id, and a human's comment left in a failed thread is read the same way.
  • Plugins are installed from a path and reloaded without a restart. The factory's plugin provides the bb factory commands, the quality gate, the phase seats per repository, and a page in bb's sidebar with the factory floor.
