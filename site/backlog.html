The Backlog

  • Home

Everything starts as a task on the Backlog: the list of tasks the factory has not started yet. A task is a request in plain words, "I want the button to be red"; turning it into a plan is Intake's job, not the Backlog's.

What goes on the Backlog is decided by humans or by automations. Sources: an issue a human opens by hand; a markdown note or a transcribed voice memo dropped in a folder, which a collection automation turns into an issue. The one exception is Intake splitting a request that does not fit one pull request: "redesign the site" becomes "new header", "new footer", "new colours", each a new factory issue linked from the original.

Every source ends as one thing: a GitHub issue with a factory label. That label is the Backlog. From that moment GitHub Issues are the queue and labels are the state machine. The factory keeps no state of its own beyond a map from running agent to issue, so the whole factory can be read, and repaired, from the issue list.

Order: first in, first out. No priorities. A task that fails and comes back to the Backlog joins at the back of the queue.

Label Meaning
factory on the backlog, waiting for a free Intake agent
factory:intake an Intake agent is turning it into a plan
factory:build a Build agent owns it in an isolated workspace
factory:review a Review agent is judging the pull request against the plan
factory:release the release automation is merging and deploying it
factory:done released
factory:failed out of attempts, or failed intake; a human looks
strike:1 … strike:5 strikes absorbed so far; five is the end

A human can unstick anything by editing a label.
