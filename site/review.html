Review has 2 seats and a 5 minute timeout. Its artifact is factory/reviews/N-A.md on the task's branch, with a link on the pull request.

Input

The task's worktree with a passing factory/gates/N-A.md, the plan in factory/plans/N-A.md, the pull request and the diff. The reviewer is told not to open the builder's thread. Before the agent starts, the factory checks that the branch merges cleanly into main; a conflict is a Review failure without a model call.

The review shape

# Review of #N, attempt A

## Criteria
- [x] criterion, as written in the plan — `path/file.ext:12-30`
- [ ] criterion — not satisfied: one sentence

## Constraints
- held / violated: which, where

## Unrequested changes
- `path/file.ext:40-52` — what it does and why it is not in the plan

## Defects
1. `path/file.ext:line` — the problem in one sentence; what resolves it

## Verdict
READY | FINDINGS

Verifiable because

The end of Review is a command. The review file exists, every criterion from the plan appears in its Criteria section with a diff reference or a reason, and the last line is one of two words. READY with any unchecked criterion, violated constraint or defect is refused as malformed.

On failure

FINDINGS is a functional failure reason and costs one strike. The task goes to the back of the Backlog and is re-processed from Intake, with the review file and a link to this thread as part of what every following agent reads.

The agent that writes is not the agent that judges

The builder sees its own plan and its own output and will grade them kindly. That is why the gate is a tool the builder runs but does not write, and why the reviewer sees only the plan, the gate report and the diff, cannot ask the builder anything, and treats a missing proof as a finding, not an oversight.

The prompt

You review a pull request produced by an unattended factory. You did not write it, you cannot ask the author anything, and you do not open the builder's thread. Read factory/plans/N-A.md, factory/gates/N-A.md and the diff. Write factory/reviews/N-A.md with exactly the sections Criteria, Constraints, Unrequested changes, Defects and Verdict, commit it to this branch, and comment on the pull request with a link to it. For each acceptance criterion, find the lines in the diff that satisfy it, or state that none do. Check the diff against the plan's constraints. List every change the plan did not ask for; unrequested changes are findings even if they are improvements. List defects: wrong behaviour, missing error handling, anything a careful colleague would not merge. The verdict is READY only if every criterion is satisfied, every constraint held, and the other two sections are empty. If it is READY, mark the pull request ready for review. Do not fix anything. Do not comment on style the quality gate already enforces.
