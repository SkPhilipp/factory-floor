# Plan for #4, attempt 2

## Goal

The Dark Factory site gets a new page, "Intake", explaining the first of the three agents: what it is given, what it must produce, how its end is verified, how it fails, and the exact prompt it runs on. A reader reaches it from the nav on the home page. Attempt 1 built this page correctly but was rejected because `site/index.html` conflicted with master: master gained the nav items Release and The loop in the meantime. This attempt delivers the same page on top of current master, so the branch merges cleanly. The issue fits one small pull request; no split.

## Scope

In:
- Bring the branch up to date: `git fetch origin && git merge origin/master`. The branch already holds `site/intake.html` from attempt 1 (52 lines, content matches the issue; keep it). Resolve the conflict in `site/index.html` by taking master's version of the file and then adding exactly one `<li>`, `<li><a href="intake.html">Intake</a></li>`, as the last item of the `<nav>` list, after The loop. If master has gained further nav items by the time of the build, keep them all and still append Intake last.
- `site/intake.html`, titled "Intake", using the shared stylesheet `style.css`, with an `<h1>` "Intake" and the content of the issue: intro (three agents, three prompts, three separate sessions; 4 seats; 8 minute timeout; artifact `factory/plans/N-A.md`), Input, Output (retry file `factory/plans/42-2.md`), the plan shape in one `<pre>` block, the proofs sentence, "Verifiable because", "On failure" (all five strikes, not retried), and the prompt verbatim in one `<blockquote>`.
- The nav of `site/intake.html` should list the same links as master's `site/index.html` nav, with Intake included, so the page links to every sibling page that exists on master (Home, Release, The loop, Intake). Every `href` must resolve, as `npm test` checks.
- What a named file needs to be valid and conventional is in scope and is not unrequested: in `site/intake.html` the `<!DOCTYPE html>`, `<html lang="en">`, `<meta charset="utf-8">`, the `<main>` wrapper, and the nav markup; HTML escaping of `&`, `<`, `>` and quotes in page text; and the merge commit that brings in master's files.

Out:
- Pages for the other agents, any other new page, JavaScript, new CSS rules, edits to `check.mjs`, `README.md`, `package.json` or `site/style.css`.
- Any change to `site/index.html` relative to master other than the one nav item.

## Constraints

- May touch only `site/intake.html` (new) and `site/index.html` (one added nav `<li>`). Files under `factory/` do not count, and files that arrive only through merging `origin/master` are not changes of this branch.
- Must not change `site/style.css`, `check.mjs`, `package.json`, `README.md`, `site/loop.html` or `site/release.html`, and must not change existing text, headings, links or the head of `site/index.html` as it is on master. No dependencies, build step or scripts.
- Must link the stylesheet as `<link rel="stylesheet" href="style.css">`.
- Budget: at most 2 commits beyond the current branch tip (the merge and, if needed, a fix); at most 2 files changed outside `factory/` relative to `origin/master`; at most 60 added lines in total and exactly 1 added line in `site/index.html`.
