# Plan for #5, attempt 1

## Goal

Add a "Build" page, `site/build.html`, describing the Build agent and the quality gate as the issue specifies, and link it from the nav on `site/index.html` as "Build". The issue is one small static page plus one nav line; it fits one pull request, no split.

## Scope

- Create `site/build.html` using the shared stylesheet, with the content below. For validity and convention it carries `<!DOCTYPE html>`, `<html lang="en">`, `<meta charset="utf-8">`, a `<title>` containing "Build", and the same `<main>` wrapper as `site/index.html`. It has an `<h1>` "Build" and a nav `<ul>` with a Home link to `index.html` and a Build link to `build.html`, mirroring `site/index.html`. These are conventional, not unrequested.
- Page content, in this order, in prose and lists (headings `<h2>` allowed):
  - Build has 2 seats and a 5 minute timeout.
  - Its artifact: commits on the branch, a draft pull request that references the issue, and a passing `factory/gates/N-A.md`, written by the quality gate and never by the agent.
  - Input: the task's worktree with `factory/plans/N-A.md` on its branch, full permissions inside it, and the quality gate as a tool (`bb factory gate`, also exposed over MCP). On a retry the branch holds the previous attempt's commits and the issue carries the failure reasons and the ids of the earlier threads.
  - The quality gate as an ordered list (`<ol>`) of 5 steps: the check command (one command for linting, formatting and tests, run from a clean install); the plan's proofs (every command under Proofs, output captured, exit code recorded); the plan's constraints (diff against `main`, files outside the allowed set and the budget, `factory/` exempt); the pull request (exists, is a draft, references the issue); the report (written by the tool to `factory/gates/N-A.md` with a link on the pull request: commit it ran against, each step pass or fail, captured output).
  - The paragraph on the agent seeing the same report, fixing and re-running within the timeout; the factory re-running the gate once against the pushed commit; a missing, failing or older-commit report being a technical failure worth one strike; the clean install cached per worktree.
  - The three failure kinds and their costs: handing off without a passing gate, one strike; the phase times out or the pull request is missing, two strikes; the agent cannot do the plan, two strikes with a functional reason; in every case the branch and the thread stay and the next attempt continues from them.
  - The prompt, verbatim from the issue, inside one `<blockquote>`, split into `<p>` paragraphs only if needed. Words the issue puts in backticks may be wrapped in `<code>`; HTML special characters are escaped.
- Edit `site/index.html`: add exactly one `<li><a href="build.html">Build</a></li>` to the existing nav `<ul>`, after the Home item. Nothing else in that file changes.

## Constraints

- May touch only `site/build.html` (new) and `site/index.html`. Files under `factory/` do not count.
- Must not change `site/style.css`, `check.mjs`, `package.json` or `README.md`, add dependencies, JavaScript, a build step, or other pages, and must not remove or reword anything already in `site/index.html`.
- Must not paraphrase the prompt or the numbers (2 seats, 5 minute timeout, one strike, two strikes).
- Budget: at most 2 files changed and under 90 added lines in total, outside `factory/`.

- [ ] `site/build.html` exists, starts with `<!DOCTYPE html>`, has `<meta charset="utf-8">`, a non-empty `<title>` and the exact line `<link rel="stylesheet" href="style.css">`.
- [ ] `site/index.html` nav contains `<a href="build.html">Build</a>` exactly once, and still contains `<a href="index.html">Home</a>`.
- [ ] The diff of `site/index.html` is one added line and no removed lines.
- [ ] `site/build.html` states 2 seats and a 5 minute timeout, and names `factory/gates/N-A.md` as written by the quality gate and never by the agent.
- [ ] `site/build.html` lists the five gate steps in the order check command, proofs, constraints, pull request, report, in an `<ol>` with 5 `<li>` items.
- [ ] `site/build.html` describes the three failure kinds with one strike, two strikes and two strikes with a functional reason.
- [ ] `site/build.html` contains the prompt from the issue inside a `<blockquote>`, starting "You build one issue in an unattended factory." and ending "...saying why, and stop.", unaltered.
