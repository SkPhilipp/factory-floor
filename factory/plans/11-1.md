# Plan for #11, attempt 1

## Goal

Add `site/floor.html`, "The floor", and link it from the nav on `site/index.html` as "Floor". The page carries the issue's text, the Fact / Source / Readable as table, and a CSS 3D scene of five phase columns with pads, lights, cards, strike dots, timeout bars, a throughput tally and merged cards sliding out to the right. It needs no WebGL, no canvas and no JavaScript.

The issue is too large for one pull request: live state, drag-to-orbit and click-to-open-thread need JavaScript and a state source that this static site does not have. It is split. This pull request ships the static page, whose scene is real markup and CSS driven by `data-*` attributes and classes, with sample state. The live feed, orbit and click-through are filed as #17 (labelled `factory`).

## Scope

- `site/floor.html`, new: doctype, `<html lang="en">`, `<meta charset="utf-8">`, a `<title>`, `<link rel="stylesheet" href="style.css">`, a `<main>` wrapper and a nav with Home and Floor links are what a valid, conventional page here needs (they match `site/index.html`) and are in scope.
- `site/index.html`: one added `<li><a href="floor.html">Floor</a></li>` in the existing nav. Nothing else changes.
- `site/style.css`: floor rules appended after the existing rules. Existing rules stay as they are.
- The page contains, in this order: an `<h1>` "The floor", the issue's intro paragraph, the table, the scene, a throughput tally, and the closing paragraph naming the ideas that did not ship first (lights-out assembly line with conveyor and scanner tunnel, semiconductor fab with defect maps, foundry with a quench, orbital shipyard, pneumatic tube sorting office).
- The table has the columns Fact, Source, Readable as and the nine rows from the issue, with the issue's wording.
- The scene has five columns, in order Backlog, Intake, Build, Review, Release. Seats in the sample state: Backlog 0, Intake 1, Build 2, Review 1, Release 1. Every pad is preceded by a light to its left; Release's single pad has a green light. Waiting cards sit dimmed below the pads.
- Sample cards cover each state: one waiting, one held by an agent (light on, card lifted), one with strikes, one timeout bar near the limit (orange), one `factory:failed` (dark, faded), one merged (slid right). Each card is an `<a>` with an issue number and title. Orbit and thread links are #17's work, so card `href`s point at `#`.
- Sample state is inert: nothing in the CSS may use `animation`, `@keyframes` or timers. State changes show through `transition` on class and `data-*` changes only.
- Not in scope: JavaScript, drag to orbit, live data, opening threads (all #17).

## Constraints

- May touch only `site/floor.html`, `site/index.html` and `site/style.css`. Files under `factory/` do not count.
- Must not change `check.mjs`, `package.json`, `README.md`, or any existing line of `site/index.html` or `site/style.css` other than the one nav item added.
- Must not add dependencies, a build step, images, `<script>`, `<canvas>`, `<svg>` WebGL or any file outside `site/`.
- Budget: at most 3 files changed outside `factory/`, at most 300 added lines in total, and at most 2 removed lines.
