# Plan for #9, attempt 1

## Goal

Add the page `site/quality.html`, titled "Quality control", that explains how a dark factory gets quality without anyone watching: the gate, artifacts with a shape, and a reviewer that trusts neither builder nor summary. Link it from the nav of `site/index.html` as "Quality". The issue is one new page plus one nav line, so it fits one pull request; no split.

## Scope

- Create `site/quality.html` using the shared stylesheet (`<link rel="stylesheet" href="style.css">`), with the content from the issue: an opening paragraph on the three sources of quality, then four parts:
  - "Artifacts with a shape": a table with columns Artifact, Path on the branch, Refused when, and three rows (plan from Intake `factory/plans/N-A.md`, gate report from Build `factory/gates/N-A.md`, review from Review `factory/reviews/N-A.md`), followed by the sentence that a refused artifact is a technical failure and the agent is told which rule it broke.
  - "What counts as proof": a table with columns Claim, Proof, Verified by, and the seven rows from the issue; then the "Not a proof" paragraph (no-output test claims, "Verified manually", a summary of what was done) and the pull request versus thread paragraph.
  - "Layers, and what each catches": a table with columns Layer, Catches, Cost, and the six rows from the issue; then the paragraph on order of cost, no human merge approval, and human review capacity being built.
  - "Failure modes": a definition list (`<dl>`, `<dt>`, `<dd>`) with the seven named modes: the confident wrong agent, the scope creeper, the flaky check, the stalled loop, the runaway loop, the conflicting pair, the unplannable request, each with the catch named in the issue.
- Edit `site/index.html`: add one `<li><a href="quality.html">Quality</a></li>` after the Home item in the existing nav. Nothing else in that file changes.
- What the new page needs to be valid and conventional, and so is planned, not unrequested: `<!DOCTYPE html>`, `<html lang="en">`, `<meta charset="utf-8">`, a `<title>`, a `<main>` wrapper, an `<h1>` "Quality control", `<h2>` headings for the four parts, `<thead>`/`<tbody>` in tables, and a nav on the page with Home and Quality links, mirroring `index.html`, so a reader can navigate back.
- `site/style.css` is used as is. Table styling already exists there.

## Constraints

- May touch only `site/quality.html` (new) and `site/index.html`. Files under `factory/` do not count.
- `site/style.css`, `check.mjs`, `package.json` and `README.md` must stay byte-identical to the branch head.
- The existing `index.html` heading, paragraph and Home link must be kept unchanged.
- Must not add dependencies, a build step, JavaScript, inline styles, a `<style>` element, or other pages.
- Must not reword the issue's table cells or definitions beyond HTML-escaping (`&`, `<`, `>`) and wrapping paths in `<code>`.
- Budget: at most 2 files changed and under 140 added lines in total, outside `factory/`.
