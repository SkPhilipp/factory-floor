# Plan for #4, attempt 1

## Goal

The Dark Factory site gets a new page, "Intake", that explains the first of the three agents: what it is given, what it must produce, how its end is verified, how it fails, and the exact prompt it runs on. A reader reaches it from the nav on the home page. The issue fits one small pull request; no split.

## Scope

In:
- New `site/intake.html`, titled "Intake", using the shared stylesheet `style.css`, with an `<h1>` "Intake" and a nav matching the home page (Home, Intake).
- Intro paragraph: three agents, three prompts, three separate sessions; an agent is a prompt handed to the harness together with a working agreement; Intake has 4 seats and an 8 minute timeout; its artifact is `factory/plans/N-A.md` on the task's branch.
- Input section: one issue from the backlog and a fresh worktree on the task's branch; on a retry also the failure reasons, the ids of the failed attempts' threads (which it opens and reads) and the branch those attempts left.
- Output section: the plan file committed to the branch and a comment on the issue linking to it; on a retry a new file such as `factory/plans/42-2.md`, so a review names which attempt it reviewed.
- A `<pre>` block with the plan shape exactly as given in the issue, then the sentence that every proof is a command and the quality gate runs all of them without judgement.
- "Verifiable because" paragraph: the plan file exists, every heading is present, there is at least one criterion, every proof is runnable.
- "On failure" paragraph: a request that cannot become a plan gets a functional failure reason; an Intake failure costs all five strikes, so the task is not retried.
- The prompt text from the issue, verbatim, in a `<blockquote>`.
- One added `<li>` in the `<nav>` of `site/index.html`: `<a href="intake.html">Intake</a>`.
- What a named file needs to be valid and conventional is in scope and is not unrequested: in `site/intake.html` the `<!DOCTYPE html>`, `<html lang="en">`, `<meta charset="utf-8">`, the `<main>` wrapper, and the same nav markup as the home page; the HTML escaping of `&`, `<`, `>` and quote characters in the page text.

Out:
- Pages for the other two agents, any other new page, JavaScript, new CSS rules, edits to `check.mjs`, `README.md` or `package.json`.
- Any change to `site/index.html` other than the one nav item.

## Constraints

- May touch only `site/intake.html` (new) and `site/index.html` (one added nav `<li>`). Files under `factory/` do not count.
- Must not change `site/style.css`, `check.mjs`, `package.json` or `README.md`, must not change existing text, headings, links or the doctype/head of `site/index.html`, and must not add dependencies, a build step or scripts.
- Must link the stylesheet as `<link rel="stylesheet" href="style.css">` so `npm test` accepts the page.
- Budget: 1 commit; at most 2 files changed outside `factory/`; at most 90 added lines in total and 1 added line in `site/index.html`.
