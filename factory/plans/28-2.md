# Plan for #28, attempt 2

## Goal

Attempt 1 built `scripts/floor-state.mjs` (producer of `site/state.json`, contract from #17) and it is on this branch; Review found four defects in it (`factory/reviews/28-1.md`). Fix them and the related cases the review did not name. Everything else from `factory/plans/28-1.md` stays as built and must keep passing (fixture values, item order, `buildModel`/`tally` compatibility, unchanged-file mtime, README `## State file` section). One pull request, no split.

The four defects and the kind each belongs to:

1. Review `defect` text is the first line matching `/fail|finding|defect|\[ \]/i`, which on an all-checked review is the `## Defects` heading. Kind: report-text extraction. Fix: the `defect` of a failing review is the first item under its `## Defects` heading (list marker and number stripped); if that section is empty or absent the text is `review findings`. For a gate it is `Gate failed: ` plus the name of the first `## check: fail` heading's check (e.g. `Gate failed: check`), else `gate failed`. The `Result`, `Commit` and title lines are never used.
2. A review counts as `ok` when `FINDINGS` appears nowhere. Kind: verdict parsing. Fix: only the first non-blank line after the `## Verdict` heading decides: `READY` is ok, `FINDINGS` is not ok. A review without that heading or with any other verdict word is not ok, text `review unreadable`. Likewise a gate is ok only on a `Result: **PASS**` line; `**FAIL**` or no Result line is not ok.
3. Failures reading issue comments or thread status are swallowed. Kind: error handling in gathering. Fix: a failing `gh` or `bb` call, or output that is not valid JSON, aborts gathering with an error naming the command and issue/thread; nothing is guessed (no `waiting`/`unknown` stand-in, no empty comments). The CLI then prints one line to stderr, exits non-zero and leaves the output file untouched. Same for the `bb factory repos list` phases call: a failing command or invalid JSON is an error; valid JSON without phases falls back to `DEFAULT_PHASES`. A git ref listing/reading failure is also an error, except that a ref with no `factory/gates` or `factory/reviews` directory simply yields no reports.
4. `writeIfChanged` does not create the output directory. Kind: output path handling. Fix: create the parent directory recursively before writing; any other write failure is reported as the one-line error with non-zero exit, no stack trace, and no leftover `*.tmp` file.

To make these testable against the real code and not a model of it: export `parseReport(kind, text)` (pure: returns `{ ok, text }`) and `gatherInputs(run)` where `run(cmd, args)` is an injectable command runner defaulting to the `execFileSync` wrapper; the CLI calls `gatherInputs()` and `gatherReports` uses `parseReport`. `buildState` stays pure.
