# Plan for #6, attempt 1

## Goal

Add the page `site/review.html`, titled "Review", describing the Review agent and its verdict, and link it from the nav on `site/index.html` as "Review". The issue fits one pull request (one new page, one nav line); no split.

## Scope

- New file `site/review.html`: a complete page with `<!DOCTYPE html>`, `<html lang="en">`, `<meta charset="utf-8">`, `<title>Review</title>`, `<link rel="stylesheet" href="style.css">`, a `<main>` wrapper, an `<h1>Review</h1>` and a nav matching the one on `index.html` (Home and Review links). These are what a valid page needs to pass `npm test` and match the existing page; they are planned, not unrequested.
- The page content, in this order, all taken from the issue text:
  1. A paragraph: Review has 2 seats and a 5 minute timeout. Its artifact is `factory/reviews/N-A.md` on the task's branch, with a link on the pull request.
  2. The input: the task's worktree with a passing `factory/gates/N-A.md`, the plan in `factory/plans/N-A.md`, the pull request and the diff; the reviewer is told not to open the builder's thread; before the agent starts, the factory checks that the branch merges cleanly into `main`, and a conflict is a Review failure without a model call.
  3. The review shape in a `<pre>` block, exactly the template in the issue (`# Review of #N, attempt A` through `READY | FINDINGS`), HTML-escaped where needed (`<`, `>`, `&`).
  4. "Verifiable because": the end of Review is a command; the review file exists, every criterion from the plan appears in its Criteria section with a diff reference or a reason, and the last line is one of two words; `READY` with any unchecked criterion, violated constraint or defect is refused as malformed.
  5. "On failure": `FINDINGS` is a functional failure reason and costs one strike; the task goes to the back of the Backlog and is re-processed from Intake, with the review file and a link to this thread as part of what every following agent reads.
  6. A short section headed "The agent that writes is not the agent that judges" (an `<h2>`), covering: the builder sees its own plan and output and grades them kindly; the gate is a tool the builder runs but does not write; the reviewer sees only the plan, the gate report and the diff, cannot ask the builder anything, and treats a missing proof as a finding, not an oversight.
  7. The prompt, verbatim from the issue ("You review a pull request produced by an unattended factory. ... Do not comment on style the quality gate already enforces."), in a `<blockquote>`.
- `site/index.html`: add one `<li><a href="review.html">Review</a></li>` to the existing nav list, after Home. Nothing else on that page changes; the existing `<h1>`, paragraph and Home link stay.
- `site/style.css` is not changed; `<pre>` and `<blockquote>` render with browser defaults. A page may be styled only through the shared stylesheet, so no inline `<style>` and no `style=` attributes.

## Constraints

- May touch only `site/review.html` and `site/index.html`. Files under `factory/` do not count.
- `site/style.css`, `check.mjs`, `package.json` and `README.md` must not change. The `<h1>`, paragraph text and Home link in `site/index.html` must not change.
- Must not add dependencies, a lockfile, a build step, JavaScript, inline styles or other pages.
- Budget: at most 2 files changed, `site/index.html` gaining exactly 1 line, `site/review.html` under 120 lines.
