## Defects

1. `site/floor.js:100-120,129-137`: `columns` and each column's seat elements are built once from the first successful fetch and never reconciled. If a later fetch has more seats for a phase, `if (!seats[n]) return;` skips the seat, so a running item that `buildModel` put in that seat is placed nowhere and disappears from the page, which is the "running item must not vanish" defect from attempt 2 again. If a later fetch has more phases, `columns[c]` is `undefined` and the destructuring on line 130 throws, so the render stops. Only the model is tested; the DOM path is not.
2. `site/floor.js:144-146`: `el.parentNode !== parent` reparents a card whenever its slot changes, not only when its `phase/status` key changes. When running item #1 finishes in a two-seat phase, running item #2 shifts from seat 2 to seat 1 and is moved with its status unchanged. This contradicts the plan's rule "a card moves only when its item's `phase` or `status` differs", and the move is not covered by a test.
