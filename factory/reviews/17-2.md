## Defects

1. `site/floor.js:41-55` — running items beyond a phase's `seats` count, and any running item in a phase with `seats: 0`, are in neither `seats` nor `queue`, so the card silently disappears (for example a third running Build item with 2 seats, or a state with fewer seats than busy threads).
2. `site/floor.js:3-8` — `barState` divides by `phase.timeout_s * 1000` with no guard: `timeout_s: 0` (as for backlog and release in the sample) with a `started_at` gives `NaN%` or `Infinity` handling, and `NaN` flows to `style.width`. An unparseable `started_at` gives `NaN` the same way.
3. `site/floor.js:132-137` — the fetch handler ignores `r.ok` and swallows every error with `.catch(() => {})`. If `state.json` is missing or malformed, the floor stays empty with no message; a failed re-fetch leaves stale state unflagged.
4. `site/floor.js:99-100` — `if (keys.get(...) !== key || !el.className) paint(el, m); else paint(el, m);` repeats the same call in both branches, so `keys` does nothing. Moreover, `render` removes every `.seat` and `.queue` and re-appends cards each fetch (`site/floor.js:92`, `site/floor.js:106-113`). Reparenting a card in the DOM on every fetch, not only when its `phase` or `status` changed, can cut off an in-flight CSS transition and goes against the plan's rule that a card moves only on a change.
5. `site/floor.js:60-71` — the card title is set once in `makeCard`, so a retitled issue never updates, and a card's seat/queue placement is never reflected in its `.card` link text.
6. `site/floor.js:138-153` — drag-to-orbit sets no `touch-action: none` on `.scene`, so touch pointers are cancelled by browser scrolling and orbit does not work on touch devices.
